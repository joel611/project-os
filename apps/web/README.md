# web

Read-only dashboard over the Coordinator HTTP API (docs/technical-architecture.md §6): projects and their sources, tickets with their activity log, project memory, and worker health. TanStack Start in SPA mode, with shadcn components on Base UI.

```sh
bun run --cwd apps/web dev     # http://localhost:5173
bun run --cwd apps/web build   # static export in dist/client
```

The dev server proxies `/api/*` to the Coordinator at `COORDINATOR_URL` (default `http://localhost:8080`), so the Coordinator needs no CORS. Data refreshes every 3 seconds.

## Static export

`dist/client` is a plain static site: `index.html` plus hashed assets. To host it:

- Serve `index.html` for any path that is not a file (`/projects/<id>/tickets/<id>` is a client-side route).
- Proxy `/api/*` to the Coordinator, stripping the `/api` prefix.

`dist/server` is a by-product of the Start build and is not needed. The shell holds only `<html>` and `<head>`: the layout renders in the browser (`ClientOnly` in `src/routes/__root.tsx`), because one prerendered shell answers every URL and a prerendered layout would hydrate against the wrong route.

## Notes

Routes live in `src/routes/`; `src/routeTree.gen.ts` is generated by the build and committed so `typecheck` works without one.

Responses are decoded with the `@project-os/contracts` schemas in `src/api.ts`, so a Coordinator change that breaks the contract shows as an error rather than a wrong screen. Like the adapters, this app may only import `contracts` and `libs/config`.

Not yet: mutations (they wait on Web UI auth, §7) and a deployment target (Compose service or static host).
