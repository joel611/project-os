# @project-os/coordinator

## 0.1.0

### Minor Changes

- [`1e9c152`](https://github.com/joel611/project-os/commit/1e9c1525f45ccebb5a8c6b4120978382dc303fb8) Thanks [@joel611](https://github.com/joel611)! - Replace the inbound log with an append-only audit log. It records every message the Coordinator receives (admin-channel and unlinked-channel messages included, org-wide only), each Channel Digest run, Worker registration, removal, first heartbeat, going offline and coming back, and Ticket creation, assignment, claim, re-queue and status changes. `GET /audit` (org-wide, `kind` and `projectId` filters) and `GET /projects/:id/audit` replace `GET /projects/:id/inbound`; the dashboard gets an Audit log page and a project Audit tab in place of the Channel tab. Existing inbound log rows are migrated. Entries older than `AUDIT_RETENTION_DAYS` (default 90) are deleted by the health sweep.

- [`4005fbe`](https://github.com/joel611/project-os/commit/4005fbe4ee887feb10f88878c07e3f3e112e2716) Thanks [@joel611](https://github.com/joel611)! - Add the Channel Digest: the Coordinator now keeps every message in a linked Discord project channel and its ticket threads, @mention or not, and once a conversation has been quiet for 30 minutes (or 6 hours after its first message) saves the decisions and lasting facts in it to Project Memory as `decision` and `note` entries. Each entry's `sourceMetadata` keeps the messages it came from, most relevant first: sender, time, a quote and a Discord link, shown under the entry on the dashboard. It runs on the health sweep's per-minute tick (Cron on Cloudflare), makes one model call per conversation (`CHANNEL_DIGEST_MODEL`, else `DEFAULT_MODEL`), and deletes the raw messages once digested or after 7 days. Per project in Settings → General: on/off (default on) and whether to post what it saved in the channel (default off). Adds the `channel_messages` table and two `projects` columns (migration `channel_digest`).

- [`d7a51a4`](https://github.com/joel611/project-os/commit/d7a51a4384f79328e3af51ac09a64a015c6d88f2) Thanks [@joel611](https://github.com/joel611)! - Add the `/source-add` Discord command: in a project channel, `link:` a GitHub repo or Google Drive folder (with an optional `alias:` and `description:`) to link it to that project. It detects the link the same way the dashboard does, now shared as `detectSource` and `suggestAlias` in `@project-os/contracts`.

- [`be64de9`](https://github.com/joel611/project-os/commit/be64de91b5eae66644a1726b5cd8118a388c117e) Thanks [@joel611](https://github.com/joel611)! - Add `GOOGLE_ALLOWED_DOMAINS` to limit dashboard sign-in with Google to Google Workspace domains. When it's set, anyone with a verified account at those domains may sign in without being listed, and every other Google account is refused, including `ADMIN_EMAILS` outside them. The `ADMIN_EMAIL` password sign-in still works. The login page names the allowed domains when Google refuses someone. Unset, nothing changes.

- [`30b9b68`](https://github.com/joel611/project-os/commit/30b9b689988692da32ebd25c5f0ccf1a4f5733fd) Thanks [@joel611](https://github.com/joel611)! - Discord members can sign in to the dashboard and see the tickets they're involved in. `/dashboard` hands out the Google link (the same as `/connect provider:Google`). Google sign-in then finds the Discord user who linked that Google account and signs in as them, as a member who sees only **My tickets**: tickets they asked for or wrote in. New `GET /me` and `GET /me/tickets` routes. `GET /tickets/:id` and its attachments are narrowed to the member's own tickets, and every other route stays operator-only. Operators whose Google account is linked the same way get My tickets too.

- [`0654fa5`](https://github.com/joel611/project-os/commit/0654fa58b671643bb1d47ccf22ecb469b1c48ac4) Thanks [@joel611](https://github.com/joel611)! - Reorganize the model env. Every model is now one `provider/model` string: `DEFAULT_MODEL` (required, the chat model and the fallback for the rest), `CHANNEL_DIGEST_MODEL` (optional, the Channel Digest) and `DECISION_MODEL` (optional, the message classifier, default `openrouter/typesafe/jev-1.14`). `SANDBOX_PI_MODEL` falls back to `DEFAULT_MODEL`. The Coordinator refuses to start without `DEFAULT_MODEL`, with a model pi-ai doesn't know, or with an old name set: `CHAT_MODEL_ID` / `CHAT_MODEL_PROVIDER`, `CHANNEL_DIGEST_MODEL_ID` / `CHANNEL_DIGEST_MODEL_PROVIDER` and `JEV_MODEL_ID` are removed, and the error names the replacement. The Channel Digest is now always available; the per-project setting turns it on or off. `JEV_MODEL_ID` is no longer exported from `@project-os/agent-runtime`.

- [`bca5f49`](https://github.com/joel611/project-os/commit/bca5f494ac662733ad4d40fda34427cac6937473) Thanks [@joel611](https://github.com/joel611)! - Operators can assign or reassign a ticket's worker from its page in the dashboard, e.g. to move a ticket off a worker that is stuck. Any ticket not yet finished (`open`, `assigned`, `in_progress`, `blocked`) can be handed to a registered device, shared or personal; it goes back to `assigned` and that device's Watcher starts it on its next poll, while the old worker loses access to it. New operator-only route `POST /tickets/:id/assign` with `{ workerId }`; the ticket's activity and the audit log record who moved it.

- [`48fe8c5`](https://github.com/joel611/project-os/commit/48fe8c5f74d213f37ac3d0d46282041122395934) Thanks [@joel611](https://github.com/joel611)! - Let dashboard operators remove a project source. `DELETE /projects/:id/sources/:sourceId` unlinks it (operators only), and the project settings page has a Remove button that asks for confirmation first. A removed channel stops routing messages to the project and can be linked again; Workers no longer see the source.

- [`c4aa859`](https://github.com/joel611/project-os/commit/c4aa859f5ef2fef50497637943181e50d9e4a5ba) Thanks [@joel611](https://github.com/joel611)! - A follow-up in a finished ticket's Discord thread now reopens the ticket instead of being turned away. A `completed` or `failed` ticket goes back to `open` with its worker and last run cleared, gets a `reopened` audit entry and a `system` event, and is placed again like a new ticket; the thread is told it was reopened (or queued). The next Worker reads the earlier result and the new ask on the same ticket. Status questions are still answered directly, and a `cancelled` ticket stays closed. A ticket that completes again gets its own completion reply.
  
  Messages in a ticket's thread are now classified with that ticket as context (title, ask, status and an excerpt of its last result), and the classifier says whether the message is about that ticket. Small talk on a finished ticket no longer reopens it. A clearly unrelated new request gets "New ticket / Part of this ticket" buttons: "New ticket" opens it in a new Discord thread and links it from the old one, "Part of this ticket" adds it as a follow-up. The Discord adapter can open a thread with no starter message (`/threads` without `messageId`).

- [`fb7c21e`](https://github.com/joel611/project-os/commit/fb7c21e7374dce697dba2ab0cd561af95af3ceef) Thanks [@joel611](https://github.com/joel611)! - Keep what Workers did. Each agent session on a Ticket is now a Run: the Watcher pipes the agent's output (Claude Code runs with its structured stream, so messages, tool calls, tool results and errors are separate events; Pi and Codex are kept as plain lines), masks secrets on the device and again on the Coordinator, and uploads it to `POST /tickets/:id/runs` in numbered chunks, saving what it can't deliver and retrying on the next poll. Sandbox sessions are recorded from the output the launcher already receives. Transcripts live in file storage, the summary in a new `ticket_runs` table, and the audit log gets `run_started` and `run_finished`. The ticket page has a Runs section with search, event-type filters and a JSONL download; admins see every Run and a requester sees the Runs of their own Tickets. Transcripts are deleted after `RUN_LOG_RETENTION_DAYS` (default 30). A Watcher keeps its transcripts on the computer with `--no-run-log` or `WATCHER_RUN_LOG=0`.

- [`e6922f3`](https://github.com/joel611/project-os/commit/e6922f308f5ef96f31352f4132b073f96c8ad877) Thanks [@joel611](https://github.com/joel611)! - Run shared tickets from a sandbox pool: Daytona, Cloudflare Sandbox and boat.dev behind one `SandboxRunner` interface, picked in `WORKER_PROVIDERS` order with per-provider caps. boat.dev joins as the third provider.

- [`1399050`](https://github.com/joel611/project-os/commit/1399050dfe82d2f9ff28c792e8bbdb047b1b3d22) Thanks [@joel611](https://github.com/joel611)! - Replace the hosted shared Watcher (`WORKER_ID`) with shared workers that admins register: `/register-worker shared:True` in the admin channel gives a one-time code, and the device joins the pool for everyone. Tickets go to the requester's own device, then a free shared device (`SHARED_WORKER_MAX_TICKETS`), then a sandbox; with none free they queue and the health sweep assigns them later. The Watcher now requires registration, `DEFAULT_WORKER_TYPE` and the classifier's `worker_type` are gone, and the dashboard groups workers into Shared pool, Personal and Sandbox sessions.

- [`46ef966`](https://github.com/joel611/project-os/commit/46ef966750827109fad42b6f1794d7e6ee82cdcb) Thanks [@joel611](https://github.com/joel611)! - Add skill sets. An Operator creates a set in the dashboard (e.g. "development"), downloads chosen skills from skills.sh into it, and clicks Update to fetch newer versions; a skill is pinned to the git tree SHA it was downloaded at until then, and stored as a zip in file storage (R2), so adding skills needs file storage configured. Jev gets a new question when any set has skills and picks a set for a new request (stored as `tickets.skill_set_id`, migration 0005). Before the ticket starts, a sandbox session pulls its set as one zip from `GET /tickets/:id/skills` with its own token, unzips it for Pi, and a Watcher unzips it into to a private folder for that one session (Claude Code and Pi; `WATCHER_SKILLS=0` turns it off). The Watcher now starts one session per assigned ticket, naming the ticket in the prompt. `SKILLS_GITHUB_TOKEN` raises GitHub's anonymous rate limit.

- [`05ff204`](https://github.com/joel611/project-os/commit/05ff2041ed8dfb4f5f2b762d132119736da84ea2) Thanks [@joel611](https://github.com/joel611)! - Rename skill sets to task types (migration renames `skill_sets` to `task_types` and `skill_set_id` to `task_type_id`; the dashboard route moves from `/skill-sets` to `/task-types`). A task type now has an Instructions text area that is added to the Worker's system prompt, Watcher and sandbox sessions alike, whenever the ticket was routed to that type. The ticket page shows which task type it used.

- [`3c3c23a`](https://github.com/joel611/project-os/commit/3c3c23a0c59a77b21223c78e0af6735c797ecb05) Thanks [@joel611](https://github.com/joel611)! - Each Worker gets a detail page in the dashboard (`/workers/:id`, opened from the sidebar): what it is, whether it is online and when it last checked in, the tickets it is working on now, every ticket assigned to it, and its own audit entries. New operator-only routes `GET /workers/:id` and `GET /workers/:id/audit`; the audit log can be filtered by Worker, with a new `audit_log_worker_idx` index.

### Patch Changes

- [`5e25017`](https://github.com/joel611/project-os/commit/5e25017e0786482b99fa74c7bb00e0a3f0f055d7) Thanks [@joel611](https://github.com/joel611)! - When a Worker blocks a ticket, the thread now hears why. `ticket_update_status` takes a `reason` for `blocked` (what the Worker needs from the people on the ticket, kept as a `status_update` event). The Coordinator shortens it to one or two sentences with an LLM turn and posts it in the ticket's thread; if that turn fails, the Worker's exact words are posted (cut at 1500 characters). With no reason it falls back to the Worker's latest comment or status update, then to the old generic line. The Worker prompt asks for a `reason` whenever it blocks.
  
  Every blocked message also says whose account the Worker acted with (`Acting as <@id> (Name).`, the author of the ticket's latest message, the same person `user_token` uses), and so does the "please `/connect`" ask, so a blocked access can be traced to a user.

- [`dd18444`](https://github.com/joel611/project-os/commit/dd1844406688c35ce5f7402a4a90e202c37f2772) Thanks [@joel611](https://github.com/joel611)! - Wire the sandbox pool into the Cloudflare Coordinator, so tickets without a registered device start a Daytona, Cloudflare Sandbox or boat.dev session there too.

- [`fb95812`](https://github.com/joel611/project-os/commit/fb95812e0ebcf8ebe35fc0cfddfb00640b68ae9a) Thanks [@joel611](https://github.com/joel611)! - Fix: the Cloudflare deploy could not turn on the Email Digest, because `alchemy.run.ts` never bound `EMAIL_DIGEST`. It also now binds `HEALTH_WORKER_STALE_MIN`, `HEALTH_UNPICKED_MIN`, `HEALTH_FOLLOW_UP_MIN`, `HEALTH_INACTIVITY_FAIL_MIN`, `CHANNEL_DIGEST_MAX_MESSAGES` and `CHANNEL_DIGEST_RETRY_MIN`. The deploy workflow now forwards the settings it was missing, and `bun run env:gh` uploads `SKILLS_GITHUB_TOKEN` as a secret. A setting the Coordinator reads but the deploy does not bind now fails a test. Internally, one module (`assembleCoordinator`) now wires the Coordinator for both targets and the test stack.

- [`0d8e6ee`](https://github.com/joel611/project-os/commit/0d8e6ee744c667efa0d5009de29ccc79fea0baa8) Thanks [@joel611](https://github.com/joel611)! - Accept GitHub repo links in any common form when adding a project source: no `https://`, `www.`, a trailing `.git` or `/`, the SSH remote `git@github.com:owner/repo.git`, or `owner/repo`. They are stored as canonical `owner/repo`. Links that aren't a GitHub repo (`github.com/owner`, `gitlab.com/owner/repo`) are rejected with a clear message, and the API returns `400 InvalidSourceLink`.

- [`4cca370`](https://github.com/joel611/project-os/commit/4cca370a20110fb35c9adc98aa248ea14e47b775) Thanks [@joel611](https://github.com/joel611)! - Move every LLM prompt into the new `@project-os/system-prompts` package: the Worker session start (formerly `apps/watcher/prompts/session-start.md`), the Coordinator's project and admin session instructions, the Sidekick instructions, the Channel Digest instructions and request, the Jev intent and executor criteria, and the completed-ticket and status-question turns. Project and admin Pi sessions now get system instructions; until now they had none. Conversations created before this keep running without them. `makeAgentRuntime` no longer takes `instructions`, `digestPrompt` and `SIDEKICK_INSTRUCTIONS` are no longer exported from `@project-os/agent-runtime`, and the sandbox launcher no longer takes `prompt`.
