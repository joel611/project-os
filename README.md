# project-os

Project-centric AI agent (see `docs/product-brief.md`). Built on Cloudflare Workers + D1 + Drizzle + Better Auth + Effect v4 (see `docs/technical-architecture.md`).

## Layout

- `packages/core` — the one shared package; `drizzle-kit` config (`drizzle.config.ts`) and generated migrations (`drizzle/`) live at its root
  - `src/libs/db` — the `Db` Effect service (`drizzle-orm/d1` over a per-request `D1Binding`)
  - `src/libs/auth` — the `Auth` Effect service (Better Auth's official `drizzleAdapter` over that same `Db`); owns `auth-schema.ts`, generated by the Better Auth CLI (see `auth.config.ts`)
  - `src/task` — the throwaway `Task` domain module (service, typed error, schema) proving the Db/Auth/Effect/D1 wiring round-trips
- `apps/api` — Hono Cloudflare Worker; mounts Better Auth under `/api/auth/*` and Task CRUD under `/api/tasks`, building a fresh `Db`/`Auth` runtime per request from `c.env.DB`
- `apps/web` — TanStack Start SPA (`spa: { enabled: true }`), no server loaders, no dependency on `packages/core`; talks to `apps/api` over HTTP

See `CONTEXT.md` for the domain vocabulary and `docs/adr/` for the reasoning behind the `Db`/`Auth` pattern.

## Getting started

```sh
cp apps/api/.dev.vars.example apps/api/.dev.vars
bun install
bun run --cwd apps/api db:migrate
bun run dev
```

- `bun run typecheck` / `bun run test` / `bun run lint` / `bun run fix` — run across every package via turborepo
- `bun run --cwd packages/core db:generate` — generate a new migration after editing a domain module's schema
- `bun run --cwd apps/api db:migrate` — apply pending migrations to the local D1 database
